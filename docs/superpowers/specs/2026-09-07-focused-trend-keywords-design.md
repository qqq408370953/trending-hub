# 两类跟风关键词热点改造设计

## 目标

将 Trending Hub 从通用社交平台热榜改造成一个只服务于跟风选题的关键词雷达。系统仅输出两类内容：

1. 游戏、软件、App、教程相关的下载意图关键词。
2. 热门人物、动漫、游戏、节日等主题相关的拼豆或拼豆图纸关键词。

系统不提供文件下载、不聚合资源链接、不收录破解或盗版内容，也不扩展为综合资讯站。

## 用户体验

首页是一个紧凑的监测面板，第一屏直接呈现两类可能爆发的关键词：

- `下载热点`：例如“某某游戏怎么下载”“某某 App 下载教程”。
- `拼豆图纸`：例如“某角色拼豆图纸”“某游戏像素拼豆”。

每条记录展示排名、关键词、趋势状态、环比变化、发现时间和信号来源。点击关键词打开公开搜索结果页，供用户继续判断是否适合创作，不跳转到下载文件。

页面不再按微博、知乎、X 等平台展示通用热榜。桌面端双栏展示两类列表，移动端单栏展示；顶部仅保留“全部、下载热点、拼豆图纸”筛选。

## 数据发现流程

### 公开信号源

系统复用无需付费密钥的公开入口：

- 抖音公开热榜接口：发现正在升温的中文话题。
- 百度热搜公开页面：补充中文搜索热点。
- Bilibili 公开排行榜接口：补充游戏、动漫、人物和教程类主题。
- 百度公开搜索联想接口：验证用户是否已经形成具体的下载或拼豆搜索表达。

任一来源不可用时只记录错误，不中断其他来源。

### 候选词生成

每次抓取先合并三份热榜的前列标题，去重并清理过长、空白或明显无效的标题。然后查询以下搜索联想：

- 固定下载种子：`游戏下载`、`软件下载`、`App 下载`、`下载教程`、`在哪里下载`。
- 固定拼豆种子：`拼豆图纸`、`热门拼豆`、`角色拼豆`、`游戏拼豆`。
- 热点扩展：对去重后的前 15 个热榜标题分别查询“标题 + 下载”“标题 + 下载教程”“标题 + 拼豆图纸”。

请求设置超时、有限并发和统一 User-Agent，避免无界抓取。系统只保留搜索联想真实返回或热榜原文直接命中的关键词，不凭空生成组合词。

### 分类边界

下载热点必须包含以下至少一种明确意图：

- `下载`
- `怎么下载`
- `在哪下载` 或 `在哪里下载`
- `下载教程`
- `安装教程`

同时，固定种子返回项或标题上下文需要指向游戏、软件、App、工具或教程；明显指向盗版、破解、外挂、激活码、网盘资源的词直接丢弃。

拼豆热点必须包含以下至少一种表达：

- `拼豆`
- `拼豆图纸`
- `豆豆图纸`
- `像素拼豆`

不符合上述两组规则的通用热点不会进入输出。

## 趋势计算

系统为每个候选词计算可复现的信号分：

- 搜索联想排名越高，基础分越高。
- 同一个词被多个种子或来源发现时叠加信号分。
- 直接出现在公开热榜中的词获得额外信号分。

`data/trending.json` 中的上一轮分数作为对比基线。当前词在上一轮存在且旧分数大于零时，环比为 `(当前分数 - 上一轮分数) / 上一轮分数 × 100%`；首次出现时标记为“新上榜”。页面明确称其为“信号环比”，不冒充平台官方搜索量。

每类按当前信号分降序排列，分数相同则优先展示搜索联想排名更高的词，最多保留 30 条。

## 数据结构与失败策略

输出数据从 `platforms` 改为 `categories`：

```json
{
  "lastUpdated": "ISO-8601 时间",
  "categories": {
    "downloads": {
      "name": "下载热点",
      "items": []
    },
    "perler": {
      "name": "拼豆图纸",
      "items": []
    }
  },
  "sources": []
}
```

关键词记录包含 `rank`、`title`、`searchUrl`、`score`、`growth`、`trend`、`source`、`firstSeenAt` 和 `stale`。所有输出 URL 只允许 `https:` 或 `http:`。

某一分类本轮抓取为空时，保留该分类上一轮数据并设置 `stale: true`；如果没有历史数据则显示空状态。这样单个外部站点临时失败不会清空整个页面，同时页面会明确提示数据沿用自上次成功抓取。

## 代码结构

- `scripts/trend-core.js`：纯函数，负责清洗、分类、拦截风险词、计分、环比和 URL 校验。
- `scripts/fetch-trending.js`：网络请求、有限并发、来源解析、历史数据回退及 JSON 写入。
- `scripts/build-html.js`：安全渲染两类关键词面板。
- `test/trend-core.test.js`：核心规则和趋势计算测试。
- `test/build-html.test.js`：使用临时数据验证页面生成、转义和链接安全。
- `data/trending.json`、`public/index.html`：提交一份符合新结构的最新快照与静态页面。
- `.github/workflows/fetch-trending.yml`：每小时执行，提供 GitHub Actions 自带令牌但不要求额外密钥。
- `README.md`：改写项目定位、数据口径、本地运行和注意事项。

现有 Node.js 20、ES Modules、Cheerio 和 node-fetch 技术栈保持不变，只使用 Node 内置测试运行器，不新增前端框架或数据库。

## 安全与合规

- 不下载、缓存或分发第三方文件。
- 不展示破解、盗版、外挂、激活码或来源不明网盘词。
- 页面文本统一进行 HTML 转义，动态链接经过协议白名单校验。
- 外链使用 `noopener noreferrer`。
- 抓取日志不输出令牌或响应正文。

## 自动化与验证

GitHub Actions 每小时运行一次抓取和构建，只有数据或页面变化时才提交。测试先于抓取和构建执行；测试失败时不部署新页面。

测试覆盖：

- 两类关键词的正向分类和无关热点剔除。
- 破解、外挂、网盘等风险词拦截。
- 去重、计分、排序、最大条数和首次上榜逻辑。
- 基于上一轮分数的信号环比计算。
- 单分类失败时沿用历史数据并标记过期。
- HTML 文本转义、危险 URL 拦截和两类筛选渲染。

最终验证包括完整测试、静态页面构建、JSON 结构检查，以及确认仓库中不再输出原来的通用平台卡片。
